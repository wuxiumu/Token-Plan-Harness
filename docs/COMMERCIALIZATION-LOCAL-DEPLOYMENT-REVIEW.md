# OPC 商业化与本地部署改进总盘点

盘点日期：2026-11-06  
项目：Token-Plan-Harness / 五棵松工作台  
用途：后续产品决策、迭代拆解与 AI 辅助执行的主参考文档  
范围：产品、角色、用户体验、技术、安全、数据、部署、运营、商业化。不是安全审计、法律意见、市场规模报告或发布批准。

## 1. 执行摘要

项目已经从个人自用脚本发展为一个能看见真实价值的本地工作台：它聚合多个 AI 订阅与 API 账号，读取部分 CLI 或官方接口配额，支持本地用量、缓存、首页编排、Markdown 域名监控、新闻/指南页面以及局域网只读分享。最清晰的产品方向仍是“个人开发者和 2–10 人小团队，本地部署优先”。

对于 OPC（一人公司）商业化，当前缺口集中在把“开发者机器上可运行”变为“陌生客户可以安全安装、理解授权、持续使用、备份迁移并获得支持”。项目现在不应被描述成企业级多租户平台、准确的跨平台账单系统或全天候 SLA 监控器。应优先把单机个人版做成可信的本地产品，然后用可选、受控、可撤销的分享能力服务小团队。

**建议的工作顺序**：

1. 先完成本机管理面的身份与请求边界，避免局域网访问被误认为已受保护。
2. 明确存储真相源和凭证保护，给用户可验证的备份、恢复、迁移流程。
3. 建立连接器能力、数据来源、覆盖范围、错误类型和缓存新鲜度契约，避免“未知”被误呈现为零或平台总额度。
4. 做干净环境安装、首次设置、升级和卸载，让非开发者能自助完成。
5. 补历史、可靠调度、异常提醒和导出，形成持续使用价值。
6. 再验证定价与 OPC 销售路径；小团队版必须等角色权限、分享生命周期和审计就绪。

## 2. OPC 的经营约束与产品假设

这里将 OPC 按 One-Person Company（一人公司）理解：产品、研发、销售、客服、发布往往由同一人承担。基于现有产品规划和代码盘点，适合低支持成本、少依赖云服务、可以异步交付的软件；不适合一开始运营托管密钥、多租户流量、全天候监控承诺或依赖供应商接口稳定性的重服务。

建议把收费价值放在**本地管理能力**：多连接管理、历史趋势、缓存与调度、告警、备份、导入导出、可选团队只读视图、安装更新与支持。上游订阅/API 由用户直接持有并支付。许可证控制本软件的高级功能，不能替代任何上游服务登录、授权或订阅，也不能承诺供应商会维持非公开接口。

需要保留为待验证假设：用户是否愿意为一张跨产品配额看板持续付费；CLI 会员配额是否是高频痛点；本地优先是否比云端“免安装”更受目标客户欢迎；个人是否会主动为家庭/同事配置分享；¥199/年个人版和 ¥999/年五人团队版的假设价格能否成立。未访谈、未试点之前，不把这些写成市场事实。

## 3. 当前项目能力基线

以下基于本次源码盘点与仓库现有产品文档。`docs/product/READINESS.md`、`ARCHITECTURE.md`、`PRODUCT.md` 是原有规划；规划中的能力不等同于实现完成。

| 领域 | 已有实现证据 | 商业化边界/待核对 |
|---|---|---|
| Web 工作台 | FastAPI、本地静态前端、hash 路由、账号管理、多账号、首页卡片排序 | 本地管理员登录与会话未建立；服务端点仍覆盖敏感管理操作 |
| 数据存储 | Redis 优先，无法连接时自动回退本地 JSON 文件；命名空间快照 | Redis 与文件没有正式迁移/恢复机制；回退可能呈现另一份数据，用户容易误判丢失 |
| 凭证 | `.env` 初始化、前台 Key 管理、回显掩码、百炼账户隔离目录权限 | 掩码不等于加密；多项 Key 仍在 Redis/文件中明文；Redis 网络与备份密钥边界未产品化 |
| 配额连接 | 百炼、智谱、Codex CLI、Kimi Code CLI、xAI 管理费用/手工记录等多源接入 | 各来源覆盖范围不同，接口会变；没有完整连接器兼容矩阵与统一重连/健康状态 |
| 用量语义 | 有订阅窗口、重置时间、本地调用统计、缓存/过期提示 | 本地调用不是平台总账单；不能把不同币种、窗口和单位直接加总 |
| Gemini/Claude/Kimi 页面 | Gemini 与 Claude 指南；Kimi 使用介绍和官方动态页面 | 内容更新与功能地区可用性需要维护；指南不等于额度接入 |
| 模型体验 | 按平台和 Key 调用文本体验，过滤禁用、过期 Key | 可能产生真实费用；用户确认、日限额、单次上限和危险 endpoint 防护待加强 |
| 域名监控 | Markdown 配置、Redis 配置、默认 baidu.com/qq.com、状态/响应时间、约 60 秒检查缓存 | 目前前端周期触发检查，浏览器关闭不构成持续监控；HTTP 状态健康不等于业务健康或全球探测 |
| 新闻 | Kimi、Gemini 官方信息抓取与缓存 | HTML/RSS 变更可能导致无数据；缺来源更新时间/抓取失败演练和内容可用性监测 |
| 局域网分享 | `/share` 只读投影、字段白名单、二维码/局域网 URL | 局域网匿名可见、没有过期/撤销/受众管理；不能承诺团队级访问控制 |
| 启停 | `run.sh` 与 `scripts/workbench.py` 提供 start/pause/restart/status | 当前偏 macOS 开发机器；依赖创建与升级、干净安装、异常恢复、卸载均不完整 |
| 运营与产品 | 有产品定位、待验证套餐、READINESS、backlog 和执行指引 | 没有可收费发布包、用户支持流程、退款条款、版本策略和更新发布门槛 |

本次仓库可见的高风险/产品化线索：`backend/config.py` 存在开发机百炼 workspace 默认值；`scripts/workbench.py` 使用 macOS 的 `fcntl` 和 `ps`；`backend/app.py` 以回环来源判断“本机”请求，但这不是身份认证；密钥存储走当前 Storage 后端；日志/使用记录及 API 模型体验需继续检查敏感内容生命周期。上述项目应当逐项核实，不能只凭静态盘点宣称漏洞已被利用。

## 5. 多维改进空间

### 5.1 产品定位与范围

- 建立明确的 Supported / Partial / Manual / Guide-only 支持矩阵，并说明每类功能依赖“API Key、控制台授权、已登录 CLI、手工录入”中的哪一种。
- 把“订阅配额”“开发者 API 账单”“本机 CLI 使用窗口”“本工作台请求累计”“手工记录”作为不同数据类型。首页允许用户看摘要，但不得把它们混合成一个总消费金额。
- 给每张数据卡增加数据来源、覆盖范围、最后成功时间、新鲜度、错误原因、连接状态。离线缓存需保留时间戳并标明旧数据。
- 功能多不代表留存高。先收敛首页到“我还剩多少、什么时候重置、数据可靠吗、需要我做什么”。模型体验和资讯指南放次级页面。
- Kimi/Google 等内容页面维护文章来源与上次成功抓取日期；供应商能力变动时更新，失败时提供官网入口。

### 5.2 首次安装和激活

- 支持一个标准安装入口：检查 OS/架构/Python/Node/Redis 可选性/端口/权限，展示检查结果，再让用户选择数据目录和是否启用局域网访问。
- 删除开发机绝对路径、开发者 workspace 默认值和仅适合作者电脑的隐式配置。示例数据必须显式标成示例，真实账户不得自动导入给新用户。
- 首次启动向导：建立本地管理员 → 选用文件/SQLite 存储（Redis 作为高级模式）→ 添加首个账号 → 测试权限 → 看见第一张有效卡片。
- 对 CLI 连接提供检测安装、登录状态、支持范围与官方文档跳转；不要静默替用户接受服务条款、地区声明或登录到不同账户。
- 错误信息按用户能行动的方式写：未安装、未登录、授权不足、网络超时、接口变更、额度不支持。提供“复制脱敏诊断”而非“粘贴全部日志”。
- 安装过程与真实 UI 至少在两台干净设备、两个非作者账号验证；新机无 Redis 时应有单一明确的存储选择，而不是悄悄落到另一套数据。

### 5.3 身份认证、网络与安全边界

- `127.0.0.1` 访问者也可能由恶意网页、DNS rebinding、Host/Origin 混淆或端口转发触达。把回环 IP 判断当作访问控制不足；先设计本地登录/随机启动密钥会话、Host allowlist、Origin/CSRF 校验和安全 Cookie。
- 本地安装默认仅绑定 loopback。局域网监听必须通过显式启用，并说明无 TLS/访客可见的风险；本机管理接口不应随只读分享一起放宽。
- 划分路由权限：匿名分享只能访问分享 token 所授权的只读投影；管理员页面与 API 必须校验会话。分享 token 应只保存 hash、设置过期和撤销、避免放入 Referer/日志。
- 需要 threat model：恶意本地网页、同 Wi-Fi 访客、窃取分享链接、恶意 Markdown、用户提供 URL、上游恶意响应、日志泄密、Redis 未授权、备份泄密。
- 出站请求做目标域名策略和 DNS/重定向二次校验，防止 URL 接口用于 SSRF。域名监控有明确的用户提交目标；模型体验自定义 endpoint 要 separate allowlist 和本地模型显式模式。
- 管理员危险操作与权限变更记审计，不记录明文 token、完整请求头或提示词正文。日志采用大小/时间轮转与明确保留期。
- 依赖锁定版本、自动漏洞告警、SBOM、签名发布物和构建来源记录。第三方 CLI 不要在无审查的情况下自动下载/执行任意版本。

### 5.4 凭证、隐私与数据控制

- 密钥采用凭证引用而不是在 UI/API 中复制明文；展示只返回 mask 和后缀。应用日志、异常和分享 payload 做统一脱敏器。
- macOS 可先评估 Keychain；其他系统需要经审查的系统凭证库或明确的主密码加密方案。定义加密密钥如何派生/恢复，不把 key 与密文放在同一个备份包中。
- 用户需能看见每个连接器“要访问什么、为什么、会不会持久保存、怎样断开/撤销”。重新授权只重置对应账号的缓存，不能串用别的登录。
- 用量记录默认只存结构化 token/成本字段，不保存完整 prompt/output。现有试用记录功能要说明是否保存正文，提供保留期限、清除全部记录和导出前预览。
- 数据目录可被用户指定；提供本地空间占用、最近备份、清理缓存（不清历史）、清除历史、彻底移除三种不同操作。
- 分享时默认排除个人账号、API Key、请求正文、成本明细与可识别工作空间 ID；提供生成前预览和访问者视角预览。

### 5.5 存储、备份、恢复与迁移

- 当前 Redis 优先并静默 fallback 到 JSON 的行为是产品风险：一种实例可能在 Redis，另一种突然在本地文件，用户只看到空数据。变成显式存储模式：个人版一个主存储（建议 SQLite），Redis 仅用于可选缓存/高级团队场景。
- 实现 schema migration/version；升级前自动建立备份，migration 做事务、验证后才切换；失败保留原库并提供清晰的恢复动作。
- 定义备份格式、包含哪些数据、排除什么密钥、密码保护和恢复兼容范围。备份不能靠“复制 data 文件夹”口口相传。
- 设计 Redis/文件现存数据向目标存储迁移：列出来源/目标和记录数 → 备份 → dry run → 导入 → 校验 hash/数量 → 用户确认切换 → 旧库保留只读一段时间 → 可回滚。
- 需要数据导出（CSV/JSON）和删除证明；账号删除时清楚说明是否保留历史统计。

### 5.6 连接器可靠性与数据可信度

- 定义统一 Connector contract：能力声明、认证类型、连接诊断、查询范围、配额单位、缓存策略、速率限制、更新时间、错误分类、版本兼容性。
- 错误归类至少含 not_configured、needs_auth、forbidden、unsupported、rate_limited、network_error、provider_error、schema_changed、timeout。
- 每个 connector 实现 timeout、重试上限、指数退避与随机抖动、并发合并、熔断/冷却；过期成功快照只能作为 stale 显示，绝不更新 timestamp 假装新数据。
- 缓存 TTL 和抓取频率分开。浏览器打开页面不是可靠的监控调度器；设置页面关闭后由本机后台每隔可配置周期采集，关闭电脑时明确暂停。
- 对每个数据字段定义单位和窗口。例如百分比是 used 还是 remaining；时间统一存 UTC ISO-8601，显示本地时区。缺值为 null，不能转 0。
- 建立契约样本和脱敏 fixture；每个供应商 API/schema 更新时能验证 parser。失败路径、超时、过期缓存、账号隔离比重复的正常路径测试更有价值。
- README/官网页面展示“已验证日期、支持版本、限制、人工/自动”，明确非公开接口或 CLI 使用是否符合供应商条款需逐个核实。

### 5.7 监控告警与域名健康

- 当前域名检查做 HTTPS HEAD/必要时 GET，前端间隔请求 API；需要标注它测的是“该主机从本地网络可达”，不是 DNS 全链路、证书生命周期、真实用户体验或业务接口健康。
- 后台 scheduler 应由单个进程负责，持久记录最近状态和转变；网页关闭后仍按设置执行。多实例时需 Redis/数据库锁避免重复采集。
- 告警需可配置：状态连续失败 N 次才触发、恢复通知、冷却时间、静默时段、测试通知、重复去重。初版可用桌面/页面内提醒，邮件/钉钉/企业微信作为之后可选渠道。
- 频率和并发受控：限制域名数量和最低采集间隔；DNS 解析检查拦私网、loopback、link-local、云 metadata 地址和重定向；验证 TLS 与域名。
- 加入可配置检查种类：DNS、HTTPS、TCP 端口、HTTP 状态、关键词、可选自定义路径。每一种明示探测源与超时。
- 历史趋势用明确保留窗口，并能导出；异常详情提示“从本机探测”“最近 N 次失败”“响应时间”。不直接声称 SLA 百分比。

### 5.8 UI/UX、多设备和无障碍

- 桌面/iPad/手机适配以真实断点验证。鼠标拖动之外必须有键盘排序；触控卡片操作大小符合易点选；避免在大屏页堆调试与配置字段。
- 状态颜色同时配文字/图标，支持色弱、键盘焦点、屏幕阅读器和减少动画偏好。异常通知不能仅靠闪烁或红色。
- 每个卡片给唯一主数字及解释：“剩余 88%”“数据截至 09:42”“刷新失败，显示 2 小时前缓存”。
- Markdown 编辑器给实时预览、语法/行号错误、保存确认、取消未保存变更提示、恢复上次版本；不能只以正则静默忽略无效行。
- 顶部、页面标题、浏览器标题、导航当前状态统一产品名；中文/英文术语解释一致。资讯内容显示发布时间和抓取时间不同含义。
- 提供颜色对比、窄屏、浏览器缩放 200%、系统减少动态、纯键盘流程的验收清单。

### 5.9 发布、升级与支持运营

- 建立版本号、变更记录、兼容/迁移说明、签名 artifact、依赖清单和校验哈希；用户能知道版本来源和更新范围。
- 自动更新必须先有备份与失败回滚；支持离线升级包，明确是否需要网络下载 CLI/浏览器依赖。
- 安装器先做 dry-run：权限、端口、目录、已有实例、Redis/SQLite连接、可写空间。禁止默默杀其他端口进程。
- 维护 LTS/支持版本范围、已知问题、供应商接口变化公告。OPC 要有客服响应时间和受支持平台清单，别卖无能力履行的 SLA。
- 故障支持建立 runbook：启动失败、端口冲突、凭证失效、迁移失败、分享无法访问、provider schema change。诊断包默认本地生成、脱敏预览、用户手动发送。
- 许可/支付/退款/隐私政策、商标与第三方名称使用、CLI 分发及供应商条款核对都是商业发布工作流门槛，不由技术可行性自动覆盖。

### 5.10 OPC 的商业与客服可持续性

- 按价值边界设计套餐：免费本地基础；个人付费历史、定时采集、备份提醒、多连接；团队版分享权限、审计和团队报表。具体额度上限/价格要用用户研究验证。
- 不做高成本云端托管，意味着通过购买页面、许可证邮件、文档、自动诊断和可复制错误报告来降低人工支持。
- 记录匿名产品指标应 opt-in，且不收集 prompt、token、账号名称、域名列表、供应商账户标识。建议先不做遥测，用明确用户反馈收集。
- 形成每月维护预算：依赖更新、供应商接口监控、工单处理、退款准备金、签名发布成本。连接器越多，维护成本越高，优先按用户价值/稳定性决定接入顺序。
- 评估开源核心+付费维护、一次性永久授权+更新期、年度订阅三种模式。个人 OPC 需要避免永久授权但持续承担无限供应商变更维护的承诺。

## 6. 优先级、验收目标和建议阶段

优先级：P0 = 安全/数据完整性/诚实销售的阻断项；P1 = 形成可用留存与可付费试点；P2 = 团队扩展与效率增强；P3 = 只有需求证据后考虑。负责人暂以 Founder/Eng/Design/Support 角色表示，不是现实人员指派。

| ID | 优先级 | 改进主题 | 用户价值/风险 | 可验收结果 |
|---|---|---|---|---|
| SAFE-01 | P0 | 本机管理员认证、会话与 CSRF/Origin/Host 边界 | 防止任意本机网页/网络请求修改账户 | 未授权写请求一律拒绝；本机合法登录可用；伪造 Host/Origin、回环假冒与重放测试通过 |
| SAFE-02 | P0 | 默认 loopback、显式 LAN 模式与分离分享 API | 不把 LAN 暴露误当成安全本地 | 新装仅本机；启用 LAN 有说明；管理接口在远端不可达；分享字段白名单有自动验证 |
| DATA-01 | P0 | 选定单一事实存储并消除静默 fallback | 避免“数据去哪了”与双库分叉 | 启动显示存储类型/路径；连接失败阻止写入或要求用户显式切换；SQLite/Redis迁移 dry-run、备份、校验、回滚 |
| CRED-01 | P0 | 凭证库和 API/日志脱敏 | 避免 Key 泄露 | 所有写路径、响应、异常、日志和诊断包均测 secret 不出现；主密码/系统凭证库方案文档化 |
| CONN-01 | P0 | 连接器能力/错误/来源/范围标准 | 避免不准确地声称总额度 | 每 connector 有能力矩阵、错误码、覆盖范围；unknown!=0；schema/timeout/auth fixtures 可验证 |
| SHARE-01 | P0 | 分享配置、预览、token expiry/revoke | 避免个人数据被任意分享 | 创建时选择字段/账号；过期、撤销即时失效；任何 API/HTML/缓存不含 Key 或被禁字段 |
| ONB-01 | P0 | 清洁环境安装和首次添加账号 | 支持陌生用户自己上手 | 两台新设备 10 分钟内完成首卡；无开发者路径、隐式账号、Redis 时有明确提示 |
| BACKUP-01 | P0 | 加密/排除密钥的备份、恢复和卸载策略 | 用户信任与迁移 | 备份前显示内容；故障演练能在干净设备恢复非密钥数据并重新授权；卸载有保留/删除选择 |
| CONN-02 | P1 | 后台采集调度、限速和失败重试 | 电脑运行时浏览器关闭仍更新 | scheduler 唯一、间隔可配、超时有上限、失败退避、状态保留 stale 元数据 |
| ALERT-01 | P1 | 域名/配额异常通知和恢复通知 | 从“看板”变“及时行动” | 连续失败去重、恢复通知、静默、测试通知；默认不重复骚扰 |
| HIST-01 | P1 | 配额/状态/连接历史和导出 | 看趋势、审计、复盘 | 保留期可配置、CSV/JSON 导出、删除可控；不同单位分开图表 |
| UX-01 | P1 | 首次连接向导、连接诊断与空状态 | 降低上手和客服成本 | 每个 provider 有安装/登录/权限/网络下一步；测试失败不要求用户读日志 |
| REL-01 | P1 | 干净环境升级/回滚和兼容矩阵 | OPC 无法人工逐台修复 | macOS 至少 2 个受支持版本测试；Linux/Windows 清楚标未支持；升级失败恢复可验证 |
| DOC-01 | P1 | 公开支持矩阵、隐私与数据流说明 | 诚实销售、减少投诉 | 每个来源标自动/手工、范围、验证日期、权限和限制 |
| BILL-01 | P1 | 价格/试用/退款和许可验证 | 形成可收款路径 | 用户研究支持价格与价值；许可证/退款/更新政策审阅完成后才开放销售 |
| TEAM-01 | P2 | 团队用户、角色与审计 | 小团队安全共享 | RBAC 和管理员/成员/只读访客测试；账号所有权/个人隐私不会继承分享 |
| TEAM-02 | P2 | 团队报告、按人/项目分类 | 管理层决策 | 只有用户主动配置归属时汇总；来源/币种/范围仍可区分 |
| O11Y-01 | P2 | 可选、脱敏、opt-in 产品诊断 | 减少 OPC 支持开销 | 关闭即零遥测；上传前预览/同意；内容不含敏感标识 |
| DIST-01 | P2 | 签名安装包、软件供应链清单 | 降低安装警告与不可信感 | artifact 签名、SBOM、hash、来源说明、回滚版本可访问 |
| ADV-01 | P3 | 多区域真实探测、业务 URL 检查 | 增强域名监控可信度 | 只有验证探测节点与授权成本后规划，不将单机探测包装成全球 SLA |

### 建议阶段门

**Stage A：内部可信单机版**  
完成 SAFE-01/02、DATA-01、CRED-01、CONN-01、ONB-01。只允许开发者与邀请测试，不公开收款。分享先关闭或限定于可信本机网络。

**Stage B：个人付费试点**  
Stage A 全部验收；补 SHARE-01、BACKUP-01、CONN-02、HIST-01、UX-01、REL-01、DOC-01。至少两个陌生用户/两台干净设备完成无人工协助安装；错误指标可解释；再进行限量付费试点。

**Stage C：OPC 正式销售**  
退款、服务条款、隐私说明、第三方连接器许可/商标审阅、支付与版本更新政策、支持边界全部就绪。达到 PRODUCT.md 的试用留存/付费门槛或更新用户研究后定价。

**Stage D：小团队版**  
实施 TEAM-01/02、可撤销分享、审计与升级支持；真实角色隔离验证完成后才宣传团队权限。不要先把匿名 LAN 链接改名叫企业协作。

## 7. 不同角色的产品验收旅程

### 个人开发者

1. 从官网获得可信安装包，看到 OS/版本支持范围。
2. 选择数据目录，设管理员，首选 SQLite；已有 Redis 用户由迁移向导处理。
3. 添加一个上游 Key 或 CLI 账号，看到此连接需要什么权限和会采集哪些字段。
4. 成功后卡片显示来源、覆盖范围、最后成功时间和重置时间；登录过期有单独的恢复说明。
5. 重启、断网、升级后数据仍在；能备份、导出、清除。

### 小团队管理员

1. 安装时默认不开 LAN 管理；建立管理员账户。
2. 选择要公开的连接和字段，预览同事看到的画面。
3. 生成限时链接，查看访问记录，并能立即撤销。
4. 成员只能看被授权的汇总，不能管理个人 Key、查看提示词或更改配置。
5. 备份/迁移实例时分享 token 依策略撤销或迁移，并有审计记录。

### OPC 客服/支持人员

1. 用户可复制错误编号与诊断摘要，不含 Key。
2. 诊断页明确版本、OS、存储模式、最近连接失败原因、是否过期缓存。
3. 用户自己选择导出并预览；客服按 runbook 判断环境、授权、网络、schema 变化。
4. 修复补丁有版本号和回滚路径，避免远程手改客户数据文件。

### 安全审查者

1. 检查本地监听/认证/Host/Origin/CSRF 请求模型。
2. 检查 Key 存储、备份、日志、异常、响应、导出和删除路径。
3. 查看每个 connector 出站地址、重定向策略、超时、缓存隔离和 schema 更新策略。
4. 查看分享授权数据模型和负向测试。
5. 查看依赖锁定、SBOM、发布签名和安全问题响应责任人。

## 8. KPI 与证据，不追虚荣指标

| 指标 | 建议定义 | 初期目标/用途 |
|---|---|---|
| 首张可信卡耗时 | 从首次打开到第一张来源/范围明确的成功卡片 | 中位数 ≤10 分钟；拆分 CLI 登录耗时与工作台耗时 |
| 首次连接成功率 | 按连接器分别算“授权成功且首次查询成功” | 先建基线；不能把不支持/地区限制混成总体错误 |
| 自动自助率 | 用户不联系开发者完成安装、连接、备份/恢复 | 邀测阶段 ≥80% 目标，与访谈问题结合 |
| 核心连接器可用率 | 在上游可用样本中，查询成功/有效尝试 | 按来源分别展示，剔除供应商 outage 后注明口径 |
| 缓存准确呈现 | 所有 stale 数据有旧时间、没有伪造新鲜时间 | 必须 100%；未知/null 永远不显示成 0 |
| 分享泄露用例 | 已撤销/过期/超字段请求失败 | 必须 100% 负向用例拒绝 |
| 备份恢复成功率 | 干净设备恢复测试成功数/演练数 | 发版前 100%，记录真实时间和失败情况 |
| 第 2 周留存 | 第二周仍至少每周使用 3 次的试点用户比例 | PRODUCT 当前假设 ≥50%，小样本只作方向依据 |
| 付费意愿 | 明确价格/替代方案/拒绝原因的真实访谈 | 目标至少 3 个愿意付费试点，不用点赞和注册数代替 |
| OPC 支持负担 | 每名付费用户每月需人工支持分钟数/问题类型 | 建立基线，若持续过高先修 Onboarding 而非增加销售 |

所有指标应明确分母、时间窗、来源和收集方式。非必要遥测默认关闭；小样本不装作统计显著。

## 9. 建议决策清单

下列决策由产品负责人明确，工程可先实现可逆的默认值与迁移工具，但正式收费前须定案：

- 品牌名、域名、商标检索与公司/收款主体。
- 是否开源核心、许可证模式、CLI 与供应商品牌的商用/再分发限制。
- 个人版和团队版价格、月付/年付、试用时长、退款期限与支持 SLA。
- macOS 首发系统版本/芯片范围；Linux 排期；Windows 是否暂不支持。
- 默认 SQLite 与 Redis 高级模式是否成为最终存储决策。
- 局域网分享默认关闭还是需明确 opt-in；是否支持企业内部 TLS 代理。
- 是否采用匿名可选诊断、收集哪些最小指标、保留多久。
- 上游连接器故障时的责任边界与支持范围。
- 离线许可证验证、宽限期和到期后保留用户读取/导出能力的机制。

## 10. 适合交给 AI 按任务执行的约束

此文件是盘点，不是向 AI 授予独立发布或访问真实账户的权限。后续每项实施任务建议采用：

1. 一次只选一个 ID，先读 `docs/product/EXECUTION.md`、`READINESS.md` 与相关代码。
2. 写出影响文件、数据迁移、权限/网络边界和回滚计划；已有真实数据、凭证和未提交变更必须保留。
3. 先做失败条件/数据契约，再实现；用合成账号、mock provider 和临时数据库验证。
4. 不运行会消耗真实额度的调用，不导出或上传用户密钥/日志，不切换存储源，不开放 LAN/公网，除非该任务明示并经过相应审批。
5. 只在证据足够时将 backlog 状态改成 done；每个验收项链接测试、截图或人工操作记录。
6. 需要域名、支付、法律主体、商标、用户数据上传或外部发布等新决策时，暂停相关步骤并向产品负责人具体提问。

此顺序与现有 `docs/product/backlog.json` 的 SEC-001、DATA-001、ONB-001 等任务对齐；正式执行前要做一次去重与依赖校准，避免创建两套互相矛盾的任务板。

## 11. 结论

当前项目有可演示的个人价值，也已经积累足够多的产品功能；它距离可收费本地部署产品的差距主要是信任与运维：用户身份、凭证、单一数据真相、升级恢复、连接器契约和可控分享。优先做好这些基础，比继续叠加更多 provider 卡片更符合 OPC 的人力和现金流约束。

推荐从安全与数据完整性开始，之后建立清洁安装和备份恢复，再做后台调度、历史与提醒。达到可独立安装、可诊断、可恢复的门槛后，才做小规模付费试点。团队角色、门户和许可证扩展必须由真实付费需求触发。
