# 产品与商业方案

## 定位

工作名：AI 用量管家（品牌和商标尚未确定）。

一句话：把分散的 AI 会员配额、API 费用和本地调用记录，汇总成可解释、可追溯的本地工作台。

用户购买的价值：减少逐个平台查额度的时间，知道数据从哪里来、何时更新、还能用多少，管理工作与个人账号，并向团队分享选定统计。

首批目标：同时使用至少三个 AI 工具的开发者，以及 2–10 人、没有专职平台工程师的小团队。优先支持 macOS；Linux 后续适配，Windows 不能在未验证时宣称支持。

## 最重要的三条使用流程

1. 首次使用：安装 → 本地管理员初始化 → 展示可接入能力与权限 → 用户选择导入账号 → 第一张真实配额卡片。目标：在满足外部登录条件时，10 分钟内完成。
2. 日常使用：看到剩余额度、重置时间、最近成功更新时间 → 异常时看到登录失效/网络故障/权限不足的区别 → 单卡刷新或重连。未知数据绝不展示为 0 或无限可用。
3. 团队分享：用户选择账号与字段 → 生成有期限、可撤销的只读链接/二维码 → 同事查看 → 管理员查看审计与撤销。现有局域网匿名分享只能算原型，不等同此目标。

## 产品结构优化

主导航目标：总览、账号与连接、用量历史、提醒、模型体验、设置。
- 总览保留海报式摘要，支持公司优先、个人折叠；同时提供紧凑列表，适合多账号。
- 卡片统一标记「官方查询 / 本地采集 / 手工记录」「订阅配额 / API 账单 / 本机调用」「实时 / 缓存 / 过期」。
- 账号与连接集中管理授权和诊断；向用户解释需要哪种权限，不只提示 CLI 错误。
- Gemini、Claude 当前先保留产品指南，不能标注为已自动接入额度。
- 模型体验明确可能产生调用费用，首屏不放无依据的推荐分；不作为第一版核心卖点。
- 新用户不自动继承开发者的账号、工作空间、路径或历史数据；演示模式只使用带标识的合成数据。

## 套餐假设（用于验证，不是已上线价格）

| 方案 | 计划内容 | 待验证价格 |
|---|---|---|
| Free | 个人本地看板、最多 3 个连接、手动刷新、数据导出 | 免费 |
| Personal | 更多连接、历史趋势、定时采集、提醒、加密备份 | ¥199/年，或对比测试 ¥29/月 |
| Team Local | 单台/单实例团队部署、角色与共享视图、审计、团队报表 | 5 人 ¥999/年，先人工报价验证 |

额度和模型费用由用户直接向模型服务商支付。付费解锁管理功能，不售卖会员额度、不共享订阅登录、不承诺绕过地区限制。许可证到期后保留读取、导出与卸载能力，不扣留用户数据。

不要一开始做云端 SaaS、多租户账单、模型中转市场、全量提示词追踪或企业 SSO。只有 Team 试点验证了真实需求，再安排这些功能。

## 验证与收入路径

以下均为目标，非已有客户或业绩：
- 访谈 10 位符合目标画像的用户，记录查额度频率、已有替代方式、愿付费场景；不收集密钥。
- 招募 5 位个人 + 2 个小团队试用 14 天；通过脱敏反馈了解问题，默认不上传遥测。
- 目标门槛：至少 80% 可独立完成接入；核心连接日成功率 ≥95%（外部服务故障分开统计）；第二周至少一半仍每周使用 3 次；至少 3 位愿意为目标价格付费。
- 未达到门槛：先改接入与留存，不堆叠更多平台。
- 达标且通过发布门槛：限量付费试点，再确定价格、退款流程、支持时段与更新服务周期。
- 分发假设：开发者内容演示、安装教程、小团队社群；每次演示使用合成账号，不展示真实数据。

## 外部参考与差异化

2026-11-04 核对官方资料：LiteLLM 已覆盖 API 网关、虚拟 Key、团队预算与费用追踪；其预算行为依赖数据库等部署条件。不要把本项目定位成一个“更全的 LiteLLM”。参考：[Virtual Keys](https://docs.litellm.ai/docs/proxy/virtual_keys)、[Budgets](https://docs.litellm.ai/docs/proxy/users)。

我们的差异化是一个**待验证假设**：跨会员订阅与 API 的轻量、本地、易理解看板，而非请求网关。连接器商业使用许可、服务条款和分发权利需逐一核对后再宣传，不因为能读到接口就认定可商用。

## 仍需产品负责人决定

发布品牌与域名、最终定价、是否开源及许可、销售主体与退款/税务安排、支持平台顺序。先做可逆的本地研发；这些决定不阻止 P0 工程整改，但阻止正式收费发布。
