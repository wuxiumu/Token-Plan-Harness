# 现状与发布门槛

审计依据：2026-11-04 本地源码。没有执行付费模型请求、扫描真实凭证或对外发布。

| 能力 | 当前证据 | 商业化判断 |
|---|---|---|
| 百炼多账号 | `backend/services/bailian_accounts.py`、账号隔离测试 | 可复用；注册仍偏脚本化，缺首次接入流程 |
| 公司只有 API Key | `stats_service.live_overview` | 仅工作台本机调用统计，不能承诺公司总额度 |
| Codex / Kimi | 各自 usage_service，通过本机 CLI | 已有采集；需兼容性矩阵、超时与重连、权限/条款核对 |
| 智谱 | `stats_service.zhipu_code_plan` | 已有自动查询；需要错误类型和契约测试 |
| Grok | `grok_usage_service.py` 与前端 | 开发者 API 与手工订阅分开，不能宣传全自动订阅同步 |
| Gemini / Claude | `frontend/js/views/stats.js` | 指南页面；不列入自动用量支持名单 |
| 分享 | `share_service.py`、`lan_readonly` | 只读与字段裁剪有效，但局域网内匿名可读，缺选择、到期和撤销 |
| 凭证 | KeyItem、key_service、本地配置目录 | 掩码只保护显示，存储仍明文；不得宣传“已加密” |
| 管理权限 | `backend/app.py` 中回环地址判断 | 不是身份认证；缺 Host/Origin 校验、本地管理员会话和 CSRF 防护 |
| 记录隐私 | `trial_service._save_trial` | 提示词与响应摘要被保存；需要默认不保存正文、保留期与删除功能 |
| 数据持久化 | Redis 优先、文件降级 | 缺明确主存储、原子迁移与备份恢复；切换可能让用户误以为丢数据 |
| 采集调度 | 前端定时器和按需查询 | 浏览器关闭后不持续采集；不能宣传“全天监控” |
| 金额 | trial/MCP 粗略估算 | 未知价格按 0、币种/价格版本未统一；不能当作精确账单 |
| 安装 | run.sh、workbench.py | 已有生命周期；有个人路径/工作空间默认值、依赖版本范围，尚非通用安装包 |

## 已实施的小步优化

- 体验页改称「模型体验」，明确是文本对话调用，移除无依据的推荐分。
- 已停用、过期或到期格式无效的 Key 在后端调用前被拒绝；前端只列启用且未到期的 Key。
- 本次不迁移真实数据、不改账号默认选择、不动个人凭证。

## 发布门槛

### M0：可安全邀请测试（P0）

SEC-001/002/003、DATA-001/002、CONN-001、ONB-001 全部完成：本地认证、凭证保护、分享可控、持久化与数据可信度、连接契约、干净环境接入。任何真实 secret 出现在日志/分享/API 响应中均视为阻断。

### M1：可进行限量付费试点

M0 + 定时采集、提醒去重、历史/导出、产品体验、可恢复安装包。验证至少 2 个不同设备/干净用户环境；外部登录失败应有恢复路径。试用效果达到 PRODUCT.md 验证门槛。服务条款、分发许可、隐私说明、支付/退款路径准备完成，最终由产品负责人确认。

### M2：小团队正式版

M1 + 成员角色、按成员/视图授权、操作审计、许可证离线宽限、升级回滚和支持流程。没有真正角色隔离之前，不把“局域网看板”宣传为“团队权限系统”。

时间粗估：M0 2–3 周、M1 再 3–4 周、M2 再 3–5 周；按一名熟悉项目的工程师估算，需在任务拆解后重估，不是交付承诺。未通过门槛不能仅因到日期就发布。

## 回归基线

`python -m unittest discover -s tests -v`；前端改动运行 `node --check` 并验证相关页面；不得用真实模型付费调用作默认测试。账号不串号、过期缓存明确标注、未知不当零、分享不泄露、停用 Key 不发请求，是持续维护的不变量。
